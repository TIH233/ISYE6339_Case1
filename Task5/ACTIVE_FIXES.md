## 2. Open Issues

### ISSUE-A — Stale output files (Task 5.9)

**Severity**: Critical — all Task 5.9 output artefacts currently on disk are wrong
**Affected files**:
- `Task5/output/lane_cost_carbon_*.csv` (all years)
- `Task5/output/subtask_5_9_cost_carbon_summary.csv`
- `Task5/data/lane_candidates.parquet`
- Cached notebook outputs in `Task5/notebooks/task5_runner.ipynb` Cell 3 and Cell 21

**Root cause**:

The saved files were generated by an **older pipeline run** using the old COST-1
equal-splits logic. In that version:

1. Each DC's annual demand was spread evenly across all **outbound** lanes only
   (DC→hub direction). Inbound and intermediate lanes received no allocation.
2. `PORT_DC` lanes (inbound: Port Rotterdam → DC) were structurally excluded
   from the outbound equal-split → `annual_flow = 0`, `cost = 0`, `co2 = 0`.
3. `HUB_CORRIDOR` lanes (hub→hub) are never DC-outbound →
   `annual_flow = 0`, `cost = 0`, `co2 = 0`.
4. `RELAY_HUB` (relay→hub second leg) was never separately allocated because
   the old code generated `DC_HUB_VIA_RELAY` pseudo-direct single lanes
   that bundled the full relay journey — the individual second leg got no flow.
5. The old code lacked the `df = df[df["annual_flow"] > 0]` filter, so all
   zero-flow lanes were written to the output files.

**Evidence**: `Task5/data/lane_candidates.parquet` contains 1,452 `DC_HUB_VIA_RELAY`
rows (generated by the old code). The **current** `hub_network.generate_lanes()`
no longer produces this lane type; it generates `DC_RELAY` + `RELAY_HUB`
two-leg paths instead.

**Fix**: Re-run the pipeline with the current code.

The current `evaluator.eval_59_lane_cost_carbon()` correctly:
- Allocates flow to lanes via route `path_lane_ids` from `service_matrix`
- Separately allocates `PORT_DC` flow via `annual_units_by_dc` dict
- Filters zero-flow lanes before returning (`df = df[df["annual_flow"] > 0]`)

**Prerequisite**: Fix ISSUE-B before re-running (prevents wrong KPIs in fresh output).

**Note on HUB_CORRIDOR**: After re-running, `HUB_CORRIDOR` lanes may still show
`annual_flow = 0` for years where all PERI_URBAN_HUBs are reachable via direct
DC→hub routes (DC_HUB_DIRECT). This is **correct model behaviour**, not a bug.
HUB_CORRIDOR only carries flow when a demand node can only be served via an
intermediate hub path, and that path survives the `DETOUR_RATIO_MAX = 1.35`
constraint in `build_routes()`.

### ISSUE-B — Per-unit KPI denominator double-counts multi-leg flow

**Severity**: High — `cost_per_unit_eur` and `co2_per_unit_kg` will be wrong
after ISSUE-A is fixed
**File**: `Task5/src/evaluator.py`, `Task5/src/pipeline.py`

**Root cause**:

`summarise_cost_carbon()` computes per-unit KPIs as:

```python
total_flow = float(lane_cost_df["annual_flow"].sum())
cost_per_unit_eur = total_cost / max(total_flow, 1)
co2_per_unit_kg   = total_co2  / max(total_flow, 1)
```

`annual_flow` is summed across **all lanes**. In a multi-leg route, the same
physical unit is counted on every leg it traverses:

- **PORT_DC + DC_HUB example (single-hop)**: 28,400 units appear once on
  `PORT_DC` (Rotterdam→DC) AND once on each DC_HUB_DIRECT lane. After the
  ISSUE-A fix, `total_flow = 28,400 × 2 = 56,800` for 2027. Denominator is
  2× the correct delivered-unit count → `cost_per_unit` halved.

- **VIA_HUB_CORRIDOR example**: Hub2 served via DC→hub1→hub2. Hub2's units
  appear on both the DC→hub1 leg and the hub1→hub2 leg. Denominator inflates
  further.

In the **current stale output** (PORT_DC flow = 0), `total_flow` coincidentally
equals delivered units (only DC_HUB lanes, one leg each), so the stale per-unit
KPIs happen to be calculated correctly. The bug only activates after ISSUE-A.

**Correct denominator**: `annual_pi_units` = total PI units delivered per year
= `service_matrix["annual_realized_units"].sum()` = `sum(annual_by_dc.values())`.

**Fix — three-file change**:

**1. `evaluator.py` — `summarise_cost_carbon()`** (lines ~721–735):

Add optional `total_units` parameter and use it as the per-unit denominator:

```python
def summarise_cost_carbon(
    lane_cost_df: pd.DataFrame,
    total_units: float | None = None,   # ← ADD
) -> dict:
    if lane_cost_df.empty:
        return {}
    total_cost = float(lane_cost_df["transport_cost_eur"].sum())
    total_co2  = float(lane_cost_df["co2_kg"].sum())
    total_flow = float(lane_cost_df["annual_flow"].sum())   # lane-level throughput
    unit_denom = total_units if (total_units and total_units > 0) \
                 else max(total_flow, 1)                    # ← USE unit_denom below
    by_type = lane_cost_df.groupby("lane_type")[["transport_cost_eur", "co2_kg"]].sum()
    return {
        "total_transport_cost_eur": round(total_cost, 0),
        "total_co2_kg":             round(total_co2, 0),
        "co2_per_unit_kg":          round(total_co2 / unit_denom, 3),    # ← CHANGED
        "cost_per_unit_eur":        round(total_cost / unit_denom, 3),   # ← CHANGED
        "by_lane_type":             by_type.to_dict(),
    }
```

**2. `evaluator.py` — `compute_all_kpis()`** (line ~906):

Add `total_pi_units` parameter and forward it:

```python
def compute_all_kpis(
    year: int,
    active_nodes: pd.DataFrame,
    lanes: pd.DataFrame,
    routes: pd.DataFrame | None = None,
    service_matrix: pd.DataFrame | None = None,
    lane_cost_df: pd.DataFrame | None = None,
    total_pi_units: float | None = None,   # ← ADD
) -> dict:
    ...
    if lane_cost_df is not None and not lane_cost_df.empty:
        cc = summarise_cost_carbon(lane_cost_df, total_units=total_pi_units)  # ← CHANGED
        ...
```

**3. `pipeline.py`** (line ~180):

Pass `total_pi_units` to `compute_all_kpis()`:

```python
kpis = compute_all_kpis(
    year, active, lanes,
    routes=routes,
    service_matrix=service_matrix if not service_matrix.empty else None,
    lane_cost_df=lane_cost_df if not lane_cost_df.empty else None,
    total_pi_units=total_pi_units,   # ← ADD
)
```

### ISSUE-C — PORT_DC `truckloads` column shows pallet-derived count, not TEU count

**Severity**: Low — cosmetic only; does not affect `transport_cost_eur`, `co2_kg`,
or any downstream profitability/KPI value
**File**: `Task5/src/evaluator.py`, `eval_59_lane_cost_carbon()` (lines ~692–711)

**Root cause**:

`eval_59_lane_cost_carbon()` applies a general truck-load formula to all lanes:

```python
df["truckloads"] = np.ceil(df["annual_flow"] / max(UNITS_PER_PALLET_PI, 1))
```

For `PORT_DC` rows, `transport_cost_eur` and `co2_kg` are then **correctly
overridden** to TEU-based ocean values per Appendix B §4:

```python
ocean_mask = df["lane_type"] == "PORT_DC"
teus = np.ceil(df.loc[ocean_mask, "annual_flow"] / max(UNITS_PER_TEU_PI, 1))
df.loc[ocean_mask, "transport_cost_eur"] = (teus * OCEAN_CONTAINER_EUR).round(2)
df.loc[ocean_mask, "co2_kg"] = (OCEAN_SAVANNAH_ROTTERDAM_KM * CO2_OCEAN_KG_KM_TEU * teus).round(1)
```

But the `truckloads` column is **never overridden** for PORT_DC rows, so it
retains the pallet-based count.

This is doubly wrong per the PDF:
1. **Wrong unit type**: ocean transport uses 6-meter containers (TEUs), not truck
   pallets. Appendix B §4: ocean cost = per-container, using TEU sizing.
2. **Wrong concept**: Appendix B §8 states **"No supplementary shipping boxes,
   fillers, or pallets are used in the PI scenario."** The PI loading unit is the
   π-pack. `UNITS_PER_PALLET_PI` in config represents the π-pack-equivalent
   truck capacity, NOT a real pallet. Using it to describe ocean container count
   is conceptually invalid.

**Impact**: `truckloads` for PORT_DC rows is a meaningless number. Any downstream
code or report reader who interprets this column as truck trips will get a wrong
answer. The `transport_cost_eur` and `co2_kg` values remain correct.

**Fix**: After the existing ocean override block, add one line to override
`truckloads` for PORT_DC rows to the TEU count used for cost/CO2:

```python
# Inside eval_59_lane_cost_carbon(), after the ocean cost/CO2 override:
df.loc[ocean_mask, "truckloads"] = teus   # ← ADD: show TEU count, not pallet count
```

## 5. AI Editing Guidance

Before editing any Task5 source file:
1. Read `Task5/CONTEXT.md` for source-of-truth rules
2. Read this file for the current issue list
3. Check whether the change touches the cost/carbon pipeline:
   - If yes: verify against Appendix B of the case PDF before editing
   - The canonical cost model is: `cost = road_km × cost_per_km × n_vehicle_trips`,
     where `n_vehicle_trips = ceil(annual_flow / UNITS_PER_PALLET_PI)` for truck

     and TEU-based override for PORT_DC (ocean leg)

   (delivered units from `service_matrix`), never the sum of lane-level flows
